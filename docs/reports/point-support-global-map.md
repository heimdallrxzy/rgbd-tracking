# normal1 地图点支撑追踪：第 3 步结果

## 结论

目标源图像 `1792225266.830730438` 的 ORB 角点和描述子在这些回放中保持一致。定位分叉发生在角点提取之后：目标帧此前实际处理的图像、上一帧的地图点关联、运动预测和地图内容不同，导致投影匹配及几何优化的输入不同。

本轮最重要的新证据是：旧的重负载 1x 记录中，目标前面隔了 132 ms 才有一帧进入 Tracking，目标帧运动模型优化只剩 2 个内点，因而没有运行 LocalMap；把详细记录限制到目标帧后，两次 1x 回放都连续处理了相邻 32 ms 图像，目标帧分别得到 60、52 个运动模型内点，并通过 LocalMap。两次轻量 1x 回放处理了相同的 832 张源图像，**但地图点和实际内点集合仍明显不同**。

因此，已确认“丢掉中间图像会改变目标帧的前序 Tracking 状态和可用匹配支撑”，也确认并行 LocalMapping 会在 Tracking 期间替换 MapPoint。现有证据仍不能把旧 1x 失败单独归因于帧间隔、某次 MapPoint 替换或地图创建延迟：输入帧保留、Tracking 状态和后台地图演化会一起变化。

## 实验设置

- 数据：`normal1_20261017_162037`，RGB-D，FIFO32，1x；与已有 FIFO32 0.25x 目标帧记录对照。
- Tracking 与 LocalMapping 保持并行。没有启用重定位恢复、上一帧观测重试、队列降载或时间间隔预测改动。
- 新增决策快照时间窗，只记录目标帧；候选/来源键记录也只覆盖目标帧。保留逐帧 profile 与输入队列事件。没有开启全程 LocalMapping、点生命周期和三角化明细，以减少诊断负载。
- 本轮没有修改匹配或建图算法，只调整诊断快照门控并新增低开销运行脚本。
- `ORB_SLAM3` 使用 `cmake --build build --target ORB_SLAM3 --parallel 8` 编译通过。该构建的主要耗时来自 `Tracking.cc` 单个大型编译单元；`--parallel 8` 不会把它拆分到多个核心。

目标源图像是 bag 中 pair 590。三次轻量 1x 的处理序列在目标帧及其之前逐张相同（目标在第 590 个处理位置），目标帧前一张处理图像均为 `1792225266.798719588`。前两次完整序列一致（832/832）；第三次在目标帧之后发生 5 次队列丢弃，因此整段长度为 827。

| 运行 | 目标 Tracking frame ID | 前序处理间隔 | 队列等待 / 目标时队列深度 | 运动匹配 → 优化内点 | LocalMap 匹配 → 优化内点 | 结果 |
|---|---:|---:|---:|---:|---:|---|
| 旧的逐帧重负载 1x | 552 | 132.010 ms | 4479.793 ms / 31 | 41 → 2 | 未进入 | RECENTLY_LOST |
| 轻量 1x A | 589 | 32.011 ms | 609.518 ms / 18 | 99 → 60 | 477 → 106 | OK，插入关键帧 |
| 轻量 1x B | 589 | 32.011 ms | 536.198 ms / 16 | 96 → 52 | 447 → 100 | OK，插入关键帧 |
| 轻量 1x C | 589 | 32.011 ms | 816.912 ms / 24 | 132 → 65 | 509 → 126 | OK，插入关键帧 |
| 0.25x 线程追踪 | 589 | 32.011 ms | 0.014 ms / 0 | 143 → 69 | 464 → 120 | OK，插入关键帧 |

各组目标图像的角点哈希均为 `16989710782197023322`，描述子哈希均为 `6088587655939181912`。旧 1x 与轻量 1x 的差别不在目标图像特征，而在前序状态：旧记录的上一帧关联哈希为 `5889215145203890135`，轻量 1x A 为 `2052517618932238232`；运动增量哈希也不同。旧记录的目标 Tracking frame ID 比轻量运行少 37，和其目标前漏掉连续源帧相符。

轻量 1x A/B 两次都没有输入队列丢帧，各处理 832 对图像；C 在目标之后丢了 5 对，目标前缀仍与 A/B 相同。旧的逐帧重负载 1x 只完成 670 对，并记录了 162 次 `frame_queue_capacity_drop_newest`。A/B/C 最大队列深度分别为 27/24/32，旧重负载运行达到容量 32。轻量运行目标帧的排队等待仍超过半秒，说明“不丢帧”不等于实时延迟很低。

## 目标帧匹配漏斗

轻量 1x A 的目标帧记录显示：

1. 运动模型输入为上一帧的 132 个 MapPoint 关联；matcher 有 4 个投影窗口没有图像特征、128 个进入描述子门限，其中 112 个通过方向一致性处理前的接受条件。方向一致性处理后得到 99 个匹配，位姿几何优化保留 60 个内点、剔除 39 个。
2. 因运动模型保留 60 个内点，Tracking 进入 LocalMap。局部地图有 3398 个候选点；其中 2042 个在 matcher 记录中可见，586 个投影窗口为空，1456 个进入描述子/ratio 判断，417 个通过并加入本帧。
3. LocalMap 优化前共有 477 个对应，优化后留下 106 个内点：其中 50 个来自运动模型阶段仍保留的点，56 个是本次 LocalMap 新匹配。其余新匹配没有通过最终几何优化。
4. 成功定位和关键帧决策之后，本帧又记录到 65 个 RGB-D 点及 32 个三角化点。这些建点发生在当前帧的定位验收之后，不能解释当前帧为何先获得 60/106 个内点。

0.25x 线程追踪中的唯一 MapPoint ID 漏斗为：204 个运动候选 → 143 个投影匹配 → 67 个运动模型优化内点；LocalMap 使用 2737 个候选，新增 396 个匹配，最终记录到 119 个唯一内点 ID（评测计数为 120）。其中 59 个运动模型内点和 60 个 LocalMap 新匹配 ID 留在最终内点集合中。一个 ID 与计数相差 1，是重复关联/按 MapPoint 去重口径不同，报告中不把两者混为同一计数。

## 来源键追踪：0.25x 支撑点在 1x 地图和候选中的位置

将 0.25x 目标帧的 67 个运动模型内点来源键，与轻量 1x A 目标帧同一时刻的记录对照。以下是“该 0.25x 点至少有一个完全相同来源观测键”的点数；它是观测来源相交，不是跨运行 MapPoint 身份判定。

| 1x A 阶段 | 67 个 0.25x 支撑点中有来源键相交 |
|---|---:|
| 运动匹配前的全局地图快照 | 45 |
| 上一帧运动模型候选 | 30 |
| 运动模型原始匹配结果 | 29 |
| 运动模型优化内点 | 22 |
| LocalMap 候选 | 46 |
| LocalMap 新匹配 | 35 |
| LocalMap 最终优化内点 | 23 |

因此，这组数据至少区分出两类支撑差异：15 个 0.25x 支撑点的来源键在 1x 全局地图快照里出现、却未出现在 1x 上一帧运动候选；另有 22 个点没有找到完全相同的 1x 全局地图来源键。第一类说明“地图里存在”不等于“会进入当前运动模型匹配”；第二类不能直接证明相同三维结构不存在，因为地图融合会改变点的来源键集合，来源键也不等于跨运行的唯一物理点 ID。

## 创建、首次有效匹配与并行替换

- 在一轮 0.25x 线程追踪中，目标帧 67 个唯一运动内点都能链接到同一运行的建点日志：31 个来自 Tracking 的 RGB-D 深度建点，36 个来自 LocalMapping 三角化；全部建点帧 ID 早于目标帧 589。36 个三角化点的实际创建时间早于目标运动匹配开始，年龄最小约 214 ms，中位约 2.70 s，P90 约 55.56 s。RGB-D 建点记录只有源帧 ID，没有独立 steady 创建时刻，故不伪造精确墙钟年龄。
- 在另一轮 8 秒宽窗 0.25x 记录中，目标 67 个运动内点里有 53 个在目标前已被优化接受过（17 个此前在运动模型内点，36 个此前在 LocalMap 内点）；49 个在窗内曾作为运动模型候选。14 个在此 1.83 秒可观察前窗内没有先前候选/内点记录，可能是更早状态、晚出现或记录窗截断，不能称为“新建点”。
- LocalMapping 的 `replace` 事件在 Tracking 目标帧运动候选到 LocalMap 搜索期间与跟踪线程重叠。线程追踪复跑中，34 个这一时间窗内的生命周期事件全部来自同一 LocalMapping 线程；其中运动模型内点 `37534` 被替换为 `24830`。替换后的点进入 LocalMap 候选并被新匹配，但没有成为最终优化内点。
- 另一轮 0.25x 生命周期记录中，62 个运动内点有 8 个在 FuseNeighbors 阶段发生替换；8 个替换目标均进入 LocalMap 候选，5 个成为本帧 LocalMap 新匹配，只有 1 个进入最终内点。两轮 0.25x 记录分别是 1/69 和 8/62，说明地图替换时序会变；它没有证明替换本身导致目标帧失跟，因为这些复跑均通过了定位。

## 同一帧序列仍有不同地图与内点集合

轻量 1x A/B 的 832 张 `track_start` 源时间戳序列完全相同，目标及其前一张图像也相同，但 target 前一帧 MapPoint 关联哈希、运动增量哈希、地图点来源和最终内点集合不同。按来源观测键计算的阶段集合 Jaccard 相似度如下：

| 阶段 | A/B 来源键交集 | Jaccard |
|---|---:|---:|
| 全局地图快照 | 17,463 | 0.261 |
| 上一帧运动候选 | 470 | 0.072 |
| 运动模型优化内点 | 205 | 0.064 |
| LocalMap 候选 | 17,966 | 0.265 |
| LocalMap 新匹配 | 1,716 | 0.100 |
| LocalMap 最终内点 | 365 | 0.067 |

尽管 A/B 两次目标帧都定位成功，60 个与 52 个运动内点中仅有 21/23 个（按 A/B 方向计）至少共享一个精确来源键。C 的运动内点为 65，LocalMap 最终内点为 126，也通过了定位。说明后台建图时序/地图演化会改变点的来源和匹配集合；但这三次目标帧都没有因此跨过 LOST 门槛。

## 证据边界与下一步

本轮证明了目标帧存在两条不同的失败/成功路径：重负载 1x 跳过前序源帧，运动模型只剩 2 个内点，因此在任何 LocalMap 补匹配之前就退出；连续处理前序帧的 1x 与 0.25x 都有足够运动支持，随后 LocalMap 能补到最终内点。低负载 1x 两次均成功，不能据此宣称 LOST 概率已降低或定位精度提高。

同时，A/B 轻量 1x 在完全相同的输入帧序列下，MapPoint 来源键和上一帧关联仍有明显差异。这支持“并行 LocalMapping 的地图演化时序影响候选和最终内点”的假设，但当前记录没有为两个 1x 复跑都开启逐点替换日志，不能指认哪一次具体地图更新造成了关联差异。目标快照及其异步写盘也仍会占用资源；宽窗 1x 的 162 次丢帧与轻量追踪的 0 次丢帧说明观测负载足以改变实验条件。

已经完成 3 次相同轻量 1x 初筛；下一步扩充配对复跑，并在每次记录目标及前序帧的 MapPoint 来源键、位姿增量、关键帧队列、LocalMapping 替换事件和首个分叉时间。随后针对“运动优化内点骤降、尚未进入 LocalMap”的出口，验证既有上一帧观测重试/扩大搜索方案。保持线程并行。若匹配数增加但未通过原几何与 LocalMap 验收，不计作救回定位。没有独立轨迹真值，不报告轨迹精度改善。
