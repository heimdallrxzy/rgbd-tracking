# normal1：ORB 运动跟踪失败后的 LK 重试实验

日期：2026-10-27  
数据：`normal1_20261017_162037` RGB-D  设备：Jetson Orin NX  
模式：ROS 2 FIFO32；Tracking 和 LocalMapping 保持并行。

## 结论

**LK 重试能在少数困难帧恢复局部地图跟踪，但这轮实验没有证明整段定位的 LOST 时长下降。**1x 三轮中触发 5 次，3 次获得至少 10 个位姿优化内点，并都进入 LocalMap 且通过了原有验收；另外 2 次只有 9 和 0 个内点，被原门限拒绝。基线与 LK 组的每轮失跟源时间都约 3.0 秒，新地图数也没有减少。

最清楚的一帧发生在同一源图像 `1792225267.630925655`：基线运动匹配从 45 个投影匹配经优化后剩 3 个，进入 RECENTLY_LOST，没有执行 LocalMap；LK 组用 273 个上一帧地图点作种子，得到 159 条有效光流、58 个当前 ORB 特征关联和 31 个几何内点，随后 LocalMap 从 263 个匹配中留下 53 个内点，帧状态保持 OK。当前帧 ORB 关键点与描述子哈希一致。

这证明该分支**有能力**在部分帧上补回几何支持，但不是严格固定上下文的单帧因果对照：两次回放的前序 MapPoint 关联、运动模型和处理间隔不同，且 1x 队列均满载、丢弃的源帧不同。因此不能把它表述为已降低 LOST 概率。

## 实验改动

- 新增可选开关 `ORB_SLAM3_OPTICAL_FLOW_RETRY=1`，默认关闭。
- 只在 RGB-D 的运动模型阶段原始匹配少于 20 个，或位姿优化后地图内点少于 10 个时尝试。
- 从上一处理帧的有效地图点观测出发做金字塔 LK 前向/反向跟踪，前后向误差不超过 1.5 px；每个光流点关联到半径 4 px 内最近且互不重复的当前 ORB 特征。
- 至少 20 个关联后才做原有位姿优化；至少 10 个有效地图内点才允许进入原有 LocalMap 跟踪。LocalMap 的匹配、优化和最终接收门限未修改。失败时恢复原帧关联。
- 为 LK 保存前一帧灰度图，Frame 拷贝只共享 OpenCV 灰度矩阵，不额外深拷贝。
- 这是**失败后辅助关联**原型：每帧 ORB 检测和描述子仍会照常计算，所以本次实验不验证前端计算加速。

## 1x FIFO32：三轮配对回放

表中是各组每轮数值的中位数；源帧输入相同，但 ROS 调度导致两次运行实际处理帧集合不完全相同。

| 指标 | ORB 基线 | LK 重试 | 说明 |
|---|---:|---:|---|
| LK 触发 / 接受 / LocalMap 通过 | 0 / 0 / 0 | 5 / 3 / 3 | 接受的 3 帧当帧均为 OK |
| 每轮 RECENTLY_LOST 帧数 | 76 | 73 | 不代表独立失跟事件概率 |
| 每轮 RECENTLY_LOST 源时间 | 3032.6 ms | 3032.7 ms | 没有下降 |
| 每轮创建地图数 | 2 | 2 | 没有减少新地图 |
| 每轮处理帧数 | 793 | 774 | LK 组因输入队列而处理的帧更少 |
| 每轮输入队列丢帧 | 38 | 57 | 三轮范围：基线 27–56，LK 组 49–65 |
| 整帧耗时中位数 | 34.46 ms | 34.70 ms | 没有可见加速 |
| 整帧耗时 p95 | 45.72 ms | 49.67 ms | LK 组未见尾延迟改善 |
| 输入队列最大深度 | 32 | 32 | 所有 1x 回放均达到容量 |

LK 尝试本身耗时为 4.0–39.3 ms。成功事件的 LK 位姿内点分别为 40、26、31；对应 LocalMap 最终内点为 80、67、53。失败事件分别是 9 和 0 个 LK 位姿内点，因此按原门限没有进入 LocalMap。

三轮中基线失跟源时间约 3000.7–3032.7 ms，LK 组约 3032.7–3036.8 ms；两边各轮都只有一个 RECENTLY_LOST 时间段且都进入过第二张地图。样本数太小，帧序列又不完全相同，不能用三轮数据判定概率差别。队列丢帧在 LK 组更多是一个需要继续监测的信号，但运行顺序、队列状态和地图演化也同时不同，不能归因为 LK 单独造成。

### 同源困难帧的细节

在 `1792225267.630925655`：

| 记录 | 基线 | LK 重试（第 3 轮） |
|---|---:|---:|
| 当前图像 ORB 哈希 | 相同 | 相同 |
| 状态变化 | OK → RECENTLY_LOST | OK → OK |
| ORB 运动投影匹配 → 优化后内点 | 45 → 3 | 70 → 低于触发门限（LK 后 31） |
| LK 有效轨迹 / 当前 ORB 关联 / LK 优化内点 | — | 159 / 58 / 31 |
| LocalMap 匹配 → 最终内点 | 未执行 | 263 → 53 |

当前图像相同，但前序状态不完全相同：基线与 LK 的前一处理帧间隔分别约 36 ms 和 68 ms，前序 MapPoint 关联哈希、运动速度哈希、输入队列等待时间也不同（约 1.44 s 与 1.61 s）。因此这是一个有价值的真实运行案例，显示 LK 分支能处理 ORB 优化崩溃的帧；它没有隔离“仅改匹配方式”的纯算法效应。

## 0.25x FIFO32：完整输入补充对照

基线与 LK 各回放一轮。两边都处理 831 帧、队列丢帧为 0、最大队列深度为 1，LK 重试没有触发。两组 RECENTLY_LOST 源时间都为 3001.1 ms，均出现一个失跟时段并经历两张地图。由于分支未触发，这只能说明它没有在这轮慢放中改变结果；也不能证明开启 LK 有帮助或有害。

## 判断与下一步

1. **保留这个可关闭原型用于定向复现，不设为默认。**它已展示几次帧级恢复，但 1x 整段失跟没有改善，且当前实现并未减少 ORB 耗时。
2. **先把 `1792225267.630925655` 的前序上下文固定后复测。**至少保存并对齐前序处理帧、上一帧关联/位姿、LocalMap 版本与队列输入序列；否则对同源图像仍是在比较不同跟踪状态。
3. **若要验证“轻量跟踪”而非失败重试，下一原型需让普通非关键帧直接使用 LK 观测坐标，并在关键帧计算当前 ORB 描述子；LK 质量不够时回退完整 ORB。**必须继续保留当前几何优化和 LocalMap 门限。当前原型仍逐帧提取 ORB，不能作为该方案的性能证明。
4. **只在重复配对回放中确认失跟时长或同地图连续跟踪改善后，才考虑合入默认路径。**当前 `normal1` 没有确认的独立轨迹真值，本报告只评估跟踪状态、地图内点和输入负载，不推断轨迹精度。
