# 项目摘要：RGB-D SLAM 跟踪失效分析与恢复尝试

## 一句话介绍

围绕 Jetson Orin NX 上 ORB-SLAM3 的 RGB-D 跟踪失效问题，我用同一段 `normal1` 数据记录输入帧、跟踪决策和地图匹配过程，分析播放速率与后台建图如何改变匹配上下文，并实现、评测了一个可选的 LK 光流恢复分支。

## 项目内容

实验从一个现象开始：相同图像能提取出相同的 ORB 角点和描述子，但在不同回放方式下，地图匹配数、优化内点和最终定位状态仍可能明显不同。为定位差异，我逐步把观测链拆成输入同步与排队、帧处理间隔、运动模型投影匹配、位姿几何验证、局部地图补匹配以及 LocalMapping 后台更新，并为代表帧保存逐帧记录。

在此基础上，我比较了直接同步处理与 FIFO 队列、正常速率与慢速回放，也复核了 BoW 重定位、扩大投影搜索窗、使用上一帧观测描述子、按处理时间间隔缩放运动预测、地图点来源追踪和稀疏光流等方案。每个方向都按最终几何内点和是否继续留在原地图评估，而不是只看原始匹配数或新建地图点数量。

最后，我在 RGB-D Tracking 中实现了一个默认关闭的金字塔 LK 失败后重试：当原运动模型的匹配或优化支持不足时，用上一帧地图点观测位置追踪当前图像，再将光流结果关联到当前帧 ORB 特征；位姿和局部地图仍经过原有几何验收。Tracking 与 LocalMapping 始终并行。

## 主要发现

- 同一目标图像的 ORB 特征一致，并不意味着跟踪输入上下文一致。前一处理帧、MapPoint 关联、运动预测和当时可用的地图候选都可能改变后续匹配。
- 有代表性的失败发生在运动模型匹配的几何优化之后：原始匹配看似充足，但只剩少量有效内点，因而未进入局部地图补匹配。
- 并行 LocalMapping 的地图支持在相同输入序列的重复运行间也会变化。记录中观察到地图更新与 Tracking 时间重叠，但现有证据不足以把并发更新认定为唯一根因。
- LK 重试在 1x 的三轮对照中触发 5 次，其中 3 次通过既有位姿和 LocalMap 门限；出现过单帧从失跟变为保持跟踪的案例。但整段 `RECENTLY_LOST` 源时间中位数与基线基本相同（3032.6 ms 对 3032.7 ms），所以不能声称它降低了整体失跟。
- 时间间隔感知预测没有显示稳定收益；部分重试方案增加了候选匹配，却仍无法通过几何门限。记录这些负结果帮助缩小了后续问题范围。

## 结果边界

这项工作目前的成果是可检查的失效分析、逐帧诊断材料、一次有明确边界的恢复原型及其负结果，不是已经验证有效的定位改进。回放队列满载时，各次运行实际处理的帧序列不同；LocalMapping 也保持并行，因此这些对照不能完全隔离单个算法因素。`normal1` 没有经过确认的独立轨迹真值，项目不报告 ATE/RPE，也不推断绝对轨迹精度提升。
